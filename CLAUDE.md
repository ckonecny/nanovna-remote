## What this is

A NanoVNA-H measures antennas from any browser on the WiFi: an Adafruit ESP32-S3
Reverse TFT Feather (#5691) is USB host for the NanoVNA, joins WiFi and serves a
web app. The firmware is a transparent WebSocket-to-USB-serial bridge; all
evaluation happens in the browser. Goal: the functions of a RigExpert Stick Pro
(single frequency, HAM bands, multi-band, charts, Smith, TDR, cable tools, OSL
calibration). Details: `docs/PROJECT.md`. **Current state, next steps, open
points: `docs/STATUS.md` — read it before starting new work.**

## Layout

## Hard rules

1. **Verify against the code and the hardware, not memory.** NanoVNA-H behaviour
   (resume, data timing, cal) is recorded in `docs/DECISIONS.md`; check it there
   before assuming.
2. **The ESP stays a transparent bridge.** No measurement maths in the firmware;
   evaluation belongs in the client. The firmware only stores data (calibration,
   WiFi networks) and runs the display UI.
3. **Build, flash and look at the device before calling a change done.** Say
   explicitly when a fix is built but not yet on the device. Firmware updates go
   over WiFi (`firmware/tools/ota.sh <ip>`); over USB hold D0 and tap RESET first.
4. **Never `git commit` or `git push` unless asked** (a request to create the
   repository or to publish counts for exactly that).
5. **After finishing a task, update `docs/STATUS.md`**: current state, next steps,
   open points. Move what is done to `docs/STATUS-ARCHIVE.md` (rule 8).
6. **Record architecture decisions and hardware findings in `docs/DECISIONS.md`**
   as they are made, not afterwards.
7. **Keep the manual current, in both languages, in the same change.** Anything a
   user can see or do differently updates `manual/manual_en.md` **and**
   `manual/manual_de.md` together — same structure, same facts, described from
   the code. Project docs (`docs/`, READMEs, code comments) are English only.
8. **Keep `docs/STATUS.md` lean**: only what is open or current, short entries,
   well under 150 lines. Finished items move (not delete) to `STATUS-ARCHIVE.md`.
9. **Feature ideas and deferred bugs live in GitHub issues** (`ckonecny/nanovna-remote`),
   in English, using `.github/ISSUE_TEMPLATE/`. End each issue Claude writes with
   `---\n_Generated by [Claude Code](https://claude.ai/code)_`. No duplicates in
   `docs/STATUS.md`. Name the issue in the commit (`Closes #N`).
10. **Licences: firmware must stay GPL-3.0-or-later, the client GPL-2.0, kept
    apart** (the client is only embedded as data). Before using anything from
    outside (library, font, snippet, asset) find its licence; incompatible or
    unclear → stop and warn the user. Compatible → record it (README "Licenses",
    `docs/DECISIONS.md`, credits). The 5x7 font is from Adafruit GFX (BSD).
11. **Mind the flash budget.** The app slot is 0x180000 (1.5 MB); `platformio run`
    prints the usage. Check it after adding features and report it when above 85 %.
12. **No local identifiers in tracked files, commits or issues**: no WiFi names or
    passwords of the user, home-network IPs, serial numbers, local paths.
    The default setup-WiFi name/password (`NanoVNA-Remote` / `nanovna-remote`) are
    public defaults and fine.
13. **No deprecated APIs.** Use the replacement right away; fix compiler and
    `npm` warnings you introduce.

## Build / run

- Client: `cd client && npm install && npm run build:esp` (output in `client/dist`,
  embedded by the firmware build). Tests: `npm test`. Dev server: `npm run dev`,
  then `?host=<ip>` (CORS blocks `/api/appcal` there — calibrate on the ESP-served page).
- Firmware: `cd firmware && python3 -m platformio run -e feather`
  (`-t upload --upload-port <port>` over USB, or `tools/ota.sh <ip>` over WiFi).
- With the USB port in host mode the Feather's USB-C shows no serial port; logs are
  at `http://<ip>/log` (ring buffer). Only a Feather in the ROM bootloader
  (D0 + RESET) or a fresh crash shows up as a serial device.
